# 评论与图片资源

博客文章、AI 快讯与留言板共用图文组件和审核机制。文字固定在上方，图片固定在下方，支持拖拽、方向键和按钮调整图片顺序，不提供自由排版。支持图片上传/粘贴、链接、粗体和预览。用户可编辑自己的内容；非管理员修改后重新进入待审核状态。

## 数据与安全

- 评论沿用 `comments`，增加可空 `digest_id`；`post_id` 和 `digest_id` 在接口中互斥。`GET /api/comments/?digest_id=6` 返回公开及本人待审核内容。未发布、撤回、未来期次不能公开查看或评论。
- 所有身份的回复都检查目标是否属于同一内容、是否有可见权限，防止跨文章/跨快讯回复和读取他人的待审核内容。
- 数据库存储文本和图片标记，图片顺序随正文持久化。服务端规范为文字在前、图片在后。前端使用 React 文本节点和固定组件，不将用户内容传给 `dangerouslySetInnerHTML`。
- 服务端拒绝 HTML、脚本、内嵌文件和危险协议。链接只允许 http/https，外链使用 `ugc nofollow noopener noreferrer`。图片必须是本站注册资源且归当前作者所有；不能引用他人上传文件。
- 图片上传要求登录，按用户和来源限流。读取字节数受限，服务端用 Pillow 识别和解码真实图片，校验像素并重编码，移除元数据和附加内容。限制策略参考 [Pillow 安全说明](https://pillow.readthedocs.io/en/stable/handbook/security.html)。

## 大小规则

| 入口 | 限制 |
| --- | --- |
| 评论、留言，以及文章/作品/个人介绍/生活动态的图片上传 | 每张 5 MiB（界面显示 5 MB）；静态 JPG、PNG、WebP；最多 2400 万像素，最长边 12000 像素 |
| 单条评论或留言 | 最多 6 张图片；普通用户正文最多 5000 字符，游客最多 2000 字符（包含存储标记） |
| AI 聊天附件 | 保持原有 8 MiB |
| AI 自动生成配图 | 保持原有 20 MiB |
| 作品视频直传 | 50 MiB，仅 MP4/WebM |

此前只有个人资料/生活动态前端校验 5 MiB，通用文章/作品直传没有明确上限。现在公共图片上传由后端校验，七牛直传令牌也配置大小和 MIME 限制。

## 引用生命周期

`media_assets` 保存存储键、所有者、大小、尺寸与清理状态；`media_references` 保存每项内容对图片的引用。文章、评论、留言、生活动态、个人资料、作品及模块、AI 快讯、保存的内容修订、用户头像均纳入引用统计。

引用在内容的同一数据库事务中更新。移除/删除内容后，提交成功才清理资源；事务回滚不会删除图片。仍被其他内容、头像、已保存修订或邮件快照使用的图片会保留。删除评论/留言的父项时同步删除回复子树及其图片引用。

暂未发表的上传保留 24 小时；清理失败记录下次重试时间。已删除/正在删除的图片不能重新引用。存储删除只操作数据库中登记且属于已知上传命名空间的键，不根据任意外链删除文件。第三方图片、网站固定命名图标和无法确认归属的旧资源不会自动删除。

`media_admin.py index` 扫描数据库及站点代码引用，默认仅预览；`--apply` 补充历史资源/引用，不执行物理删除。历史图片未知大小记为 0，新上传记录真实大小。索引可重复执行。

## 启用与验证

1. 安装 `requirement.txt` 中的新增 Pillow 依赖。
2. 执行 `python main.py db upgrade`，迁移至 `20260917_rich_comments`。
3. 加载对应环境后执行 `python media_admin.py index`，再执行 `python media_admin.py index --apply`。
4. 重启后端并发布前端；重启现有内容调度进程，调度循环会定期清理未引用图片和重试失败任务。也可执行 `python media_admin.py cleanup`。
5. `venv/bin/python -m unittest discover -s tests -p 'test_*.py'`；前端 `node --test tests/auth-store.test.cjs tests/rich-content.test.cjs`，以及 TypeScript 检查。

测试使用隔离数据库、对象存储替身与邮件替身，不向真实用户发送测试邮件，不在站点数据库插入测试发言。
