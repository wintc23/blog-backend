# 邮箱验证码登录

## 已确认的交互

设置邮箱和邮箱登录是两个独立操作。

1. 包括游客在内的已登录用户，在个人资料中填写邮箱、点击保存即可；不发送验证码。邮箱用于接收回复通知，也可在后续登录时验证归属。
2. 使用邮箱登录时，输入邮箱，获取并填写验证码，验证成功后才建立登录会话。
3. 游客填写过邮箱后，将来可以用该邮箱和验证码找回同一个用户 ID，保留昵称、头像、评论和留言。

## 登录入口

登录弹窗增加“邮箱登录”。点击后在同一弹窗内展示邮箱、6 位验证码、“获取验证码”和“登录”按钮，保留返回其他登录方式的入口。验证码支持粘贴和系统自动填充。发送失败明确提示，避免把邮件任务入队当作投递成功。

## 账号处理

| 情况 | 验证码正确后的行为 |
| --- | --- |
| 邮箱已经保存在某个账号 | 登录该账号，保留用户 ID 和已有内容 |
| 邮箱尚未对应账号 | 创建邮箱账号，自动生成昵称和头像 |
| 当前游客保存自己的邮箱 | 直接保存，不改变权限、登录状态或用户 ID |
| 设置的邮箱已被其他账号占用 | 不覆盖、不自动合并账号；提示已占用 |

设置邮箱不代表邮箱已验证。首次邮箱登录验证成功后，再记录验证时间；改变邮箱时清除旧验证状态并作废旧邮箱的未使用验证码。游客首次通过邮箱登录后成为可找回的邮箱账号；更新会话版本，使原游客身份的旧凭据失效。邮箱验证不提高原账号权限。

## 服务端

- 复用现有 SMTP 配置，使用独立验证码邮件模板。开发和测试使用邮件替身，不向真实收件人发送测试通知。
- 生成 6 位随机验证码，有效期 5 分钟；成功后原子地标记已使用，同一个验证码不能重复签发会话。
- 同一邮箱 60 秒内不能重发；验证码最多尝试 5 次。发送、验证均按邮箱和来源限流；重新发送不能重置累计错误次数。
- 验证码存服务端密钥参与计算的摘要，不存明文、不写日志；绑定邮箱、用途、挑战标识和目标账号的邮箱版本。
- 新增验证码记录，以及用户邮箱验证状态、会话版本。历史邮箱保持未验证状态，登录时完成验证。
- 用户接口仅对本人及管理员返回邮箱；公开资料不包含邮箱。
- 第一版不包含不同正式账号之间的合并。

## 验收

游客免验证设置邮箱；退出后通过正确验证码回到原账号；首次邮箱登录创建账号；错误、过期、已使用验证码均不能登录；重发和并发提交不会绕过限制；邮箱变更后旧验证码失效；QQ/GitHub 现有登录流程正常；公开接口不泄露邮箱。

## 接口与投递

- `POST /api/email-login/code/`：提交 `email`，返回 `challenge_id`、`expires_in=300`、`retry_after=60`。
- `POST /api/email-login/`：提交 `email`、`challenge_id`、6 位字符串 `code`，返回 `{token,user}`。
- 邮件主题和正文使用数据库 `personal_profiles.site_name`，正文包含账号邮箱、登录站点、验证码和“有效期：5 分钟”。SMTP 配置沿用站点现有账号；有连接超时，SMTP 失败返回 503，不返回可用验证码记录。
- 每邮箱发送上限 5 次/小时、20 次/天；每来源 20 次/小时、100 次/天。验证上限每邮箱 30 次/小时、每来源 100 次/小时。重发和来源变化不能重置单邮箱累计限制。
- 邮箱首次验证的游客转换为邮箱账号，保留头像、用户 ID 和关联内容；更新 `auth_version` 撤销原游客凭据。QQ/GitHub 原身份标识与权限保留。历史令牌在版本为 0 时继续有效。
- `20260917_email_login` 为增量迁移。测试使用隔离 SQLite 和邮件替身：`venv/bin/python -m unittest discover -s tests -p 'test_email_login.py'`。
